## 1. 手戻りを避けるための原則

1. **依存の少ない部品から積む。** 他へ依存されるもの（ジャーナル → Gate → capability → Runner）を下から順に作り、各単位で単体テストを通してから次へ進む。
2. **後続が前提にする契約を最初に固定する。** ジャーナルのイベント形式（`schema_version`、`seq`、`prev_hash`）、IDの検証規則、破損時の挙動は、P3.2の台帳が再利用するため、A1で確定する。後から変えると台帳側も壊れる。
3. **1単位 = 1コミット。** 各コミットはその時点で `SELFTEST_NON_LLM_ONLY=1` の既存結果を退行させない。
4. **既存コードは変更しない方針で始め、変更が必要になったら別コミットに分ける。** 特に `HttpTransport`/`WebFuzzer`/`FuzzAgent` への変更は、等価性試験が通る状態を保てる最小の単位にする。
5. **新経路は既定でOFF。** 既存のGUI経路は従来動作のまま（Phase Aの間は新経路をGUIへ接続しない）。
6. **開発ループ**（CLAUDE.md/AGENTS.md）: 変更→検証→修正を最大5回、同じエラーが2回連続したら止めて報告。テストの弱体化はしない。

### 2.1 最初の到達点（M1）と単位の書き方

**M1: 一本の診断が最後まで通る。** 許可したローカルWebアプリ（testlab）を、WEB FUZZ限定・逐次実行・固定計画で、
「検査 → 観測を保存 → 所見と証拠を結ぶ → 未検査理由を含む結果を出す → 各判断を追跡できる」まで通す（順8の完了で到達）。
汎用Graph・複数Worker・他モード連携・Plannerは、M1の実績から必要になった分だけ足す。順番は **M1 → 再開（Phase B） →
決定論的な優先順位（C0） → LLM Planner（C1）と比較**。それぞれ前の段階を実測で超えたことを確認してから次へ進む。

M1の合格条件（追加）: ジャーナルを読めば、任意の所見から「証拠 → それを生んだAction → その実行を許可したGate判断」まで辿れる。
レポートの「S優先」は重要度であって、全部を今すぐ作る順番ではない。

各単位は **解決する問題 → 最小変更 → 依存 → 合格条件 → 今回やらないこと** の形で書き、実装前に確認する。

| 単位 | 解決する問題 | 最小変更 | 合格条件 | 今回やらないこと |
|---|---|---|---|---|
| 3 特性化＋最小fixture | 比較の基準がなく、capability化で挙動が変わっても気づけない | 現行経路を動かして観測する試験装置とfixture（既存コード無変更） | 基準が揺れない、ground truthで手計算が合う | 本格的なベンチマーク集計（P2.1本体）、実LLM評価 |
| 3b 証拠の由来 | 証拠が削除・変更・切り詰めされても「同じ根拠で再検証できる」と誤認する | 追加フィールド4つと `verify()` | 既存出力が不変、改ざん検出 | 証拠の版の履歴、`report_evidence_version`（Phase F） |
| 4 A2 | 実行前の許可判断が型として存在せず、承認・予算の契約を試験できない | 型・Gate・予算（呼出回数・期限の次元を含む）・承認 | Gate単体試験（§11） | 承認UI、Planner |
| 5 検査実績 | 「異常なし」と「未実施」が区別できない | `WebFuzzer` に実行記録を追加（返り値不変） | 予算0／途中枯渇／ちょうど完遂 | 旧 `_build_coverage` の書換え |
| 5b LLM事前制限 | 応答後の加算では上限超過を防げず、再試行・検証パスの費用を見落とす | 呼出前ゲートと任意の `max_tokens`（追加のみ） | 呼出前に拒否される | 費用の自動切替、価格の正確な見積もり |
| 6 capability＋Runner | 統合の不整合を早期に見つけたい | 1つずつ足して毎回比較 | 比較が通る、意図的な差は期待値化 | 並列Worker、他モード |

## 3. 各単位の停止・見直し条件

- 検証が通らず、同じエラーが2回連続: 止めて原因・試したこと・残課題を報告する。
- 順6の比較で等価性が取れない: 差が意図的か（期待値に固定してよいか）を判断し、そうでなければcapability境界の切り方を見直す。比較は各capabilityの追加直後に行うので、見直しの範囲は直近の1段に収まる。
- `HttpTransport` の変更が必要と分かった: 当該変更を独立コミットにし、既存selftestの全通過を条件とする。解決先IP再検査（上位設計 §9 #8）はPhase Cの前の別単位であり、ここには混ぜない。
